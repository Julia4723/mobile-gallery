# Mobile Gallery → Figma

Отправка изображений из галереи телефона на текущую страницу открытого файла Figma.

Выбираете фото на телефоне, нажимаете «Отправить в Figma» — через пару секунд они лежат сеткой на холсте, а телефон показывает статус каждого.

Это личный MVP: один компьютер, один открытый плагин, телефоны в той же сети Wi-Fi.

## Как это работает

```
Телефон (Expo Go) ──HTTP──▶ Сервер на компьютере ◀──HTTP── Плагин Figma ──▶ текущая страница
   http://<адрес в Wi-Fi>:8787                        http://localhost:8787
```

1. Приложение загружает изображение на сервер, который работает на компьютере с Figma.
2. Сервер проверяет файл и ставит задание в очередь.
3. Плагин, пока открыт, забирает задания, вставляет изображения и подтверждает вставку.
4. Приложение показывает статус: «В очереди», «Вставляется», «Вставлено» или причину ошибки.

Телефон не выбирает файл Figma и не использует Figma REST API: изображение попадает туда, где открыт плагин.

## Состав

| Папка | Что это | Технологии |
|---|---|---|
| [`mobile/`](mobile/) | Приложение для iOS и Android | React Native, Expo SDK 57, TypeScript |
| [`server/`](server/) | Сервер с очередью заданий | Node.js 22, Fastify, TypeScript |
| [`figma-plugin/`](figma-plugin/) | Плагин Figma | Figma Plugin API, TypeScript, esbuild |
| [`docs/`](docs/) | Документация | — |

Три пакета независимы: у каждого свой `package.json`. Связывает их только HTTP API.

## Быстрый старт

Нужны Mac с Node.js 22+, настольное приложение Figma и телефон с Expo Go.

**Сервер**

```
cd server
npm install
cp .env.example .env      # укажите LAN_INTERFACE — имя интерфейса Wi-Fi, обычно en0
npm start
```

Сервер напечатает адрес для телефона и путь к файлу с токеном.

**Плагин**

```
cd figma-plugin
npm install
npm run build
```

В Figma: **Plugins → Development → Import plugin from manifest…**, файл `figma-plugin/manifest.json`. Запустите плагин и вставьте токен из `server/.token`.

**Приложение**

```
cd mobile
npm install
npx expo start
```

Отсканируйте QR-код в Expo Go. В настройках приложения введите адрес сервера и токен.

Подробная инструкция, смена IP-адреса, firewall и типичные проблемы — в [docs/connection.md](docs/connection.md).

## Возможности

- Системный выбор изображений с мультивыбором, без доступа ко всей галерее.
- Предпросмотр, удаление из списка, статус и повтор для каждого изображения.
- PNG, JPEG и GIF до 20 МБ и 50 мегапикселей. Фото в HEIC iPhone отдаёт как JPEG.
- Вставка шириной 400 px с сохранением пропорций, сетка в 5 колонок.
- Новые изображения не перекрывают существующий контент и не двигают его.
- Изображения больше 4096 px уменьшаются: это ограничение Figma.
- Повторная отправка не создаёт дубликат, в том числе после перезапуска сервера.
- Приложение различает четыре причины сбоя: сервер недоступен, неверный токен, по адресу отвечает другое устройство, плагин не запущен.

## Ограничения

- **Очередь хранится в памяти сервера.** Перезапуск её очищает; кнопка «Повторить» в приложении возвращает изображение в очередь без риска дубликата.
- **Плагин работает, пока открыто его окно**, и только в настольном приложении Figma.
- **На Android есть собственная сборка через EAS Build, на iPhone — Expo Go.** Собственная сборка для iPhone требует платной учётной записи Apple Developer. В собственной сборке Android сервер указывается по имени компьютера (`http://<имя>.local:8787`): HTTP разрешён только для имён `*.local` — см. [docs/connection.md](docs/connection.md).
- **GIF вставляется как статичное изображение.**
- **Часть сценариев не проверена вручную** — полный список в разделе 11.2 [спецификации](docs/spec.md).

## Безопасность

Доступ к серверу защищён токеном в заголовке запроса. Это временный механизм для личного использования в домашней сети:

- трафик идёт по HTTP без шифрования;
- токен один на телефон и плагин;
- сервер нельзя публиковать в интернет и запускать в общественных сетях Wi-Fi.

Сервер открывает порт только на `127.0.0.1` и на адресе одного выбранного сетевого интерфейса. Файлы `server/.token`, `server/.env` и `mobile/.env.local` исключены из git.
