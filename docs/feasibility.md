# Реализуемость: Mobile Gallery → Figma

Состояние на 2026-10-11. Документ пополняется по ходу эксперимента.

IP-адреса и имя компьютера в документе заменены условными.

Проверяемый сценарий: телефон (iOS и Android, Expo Go) в локальной Wi-Fi-сети → HTTP-сервер на компьютере → плагин в открытом файле Figma.

Документ разделён на три части, которые нельзя смешивать:

1. **Подтверждено документацией** — прочитано в официальном источнике, ссылка приложена.
2. **Результаты реальных проверок** — наблюдали сами, на этом компьютере и этих телефонах.
3. **Непроверенные предположения** — правдоподобно, но не подтверждено ни документацией, ни опытом.

## 1. Подтверждено документацией

### Figma: сеть в плагине

Источники: [Making Network Requests](https://developers.figma.com/docs/plugins/making-network-requests/), [Plugin Manifest](https://developers.figma.com/docs/plugins/manifest/), [fetch](https://developers.figma.com/docs/plugins/api/properties/global-fetch/).

- `networkAccess` содержит `allowedDomains` (обязательное, минимум один шаблон), `reasoning` и `devAllowedDomains`.
- Шаблон может начинаться со схемы `http`, `https`, `ws` или `wss`. Другие схемы запрещены.
- Для локальных серверов порт указывается после адреса. Пример из документации: `"devAllowedDomains": ["http://localhost:3000"]`.
- `devAllowedDomains` предназначен для локальных и dev-серверов и действует только при разработке.
- Если локальный сервер указан в `allowedDomains` (а не в `devAllowedDomains`), обязательно поле `reasoning`. Прямого запрета на localhost в `allowedDomains` в документации нет.
- `["none"]` запрещает весь сетевой доступ, `*` разрешает любой домен и требует `reasoning`.
- Список разрешённых доменов показывается на странице плагина в Community.
- Запрос к домену вне списка Figma блокирует с ошибкой CSP (`Refused to connect to ...`).
- У iframe плагина origin равен `null`. Из него можно вызывать только API, которые отвечают `Access-Control-Allow-Origin: *`.
- Существует собственный `fetch` Figma. Он принимает `method`, `headers` (простой объект), `body` (строка или `Uint8Array`) и возвращает `arrayBuffer()`, `text()`, `json()`.
- **IP-адреса в шаблонах документация не упоминает.** Ни разрешения, ни запрета.
- Поле `documentAccess: "dynamic-page"` обязательно для новых плагинов.

### Figma: изображения

Источник: [createImage](https://developers.figma.com/docs/plugins/api/properties/figma-createimage/).

- `figma.createImage(data: Uint8Array)` принимает только PNG, JPEG и GIF.
- Максимальный размер — 4096 px по ширине и по высоте.
- Ошибки: `Image is too small`, `Image is too large`, `Image type is unsupported`. Повреждённый файл тоже вызывает ошибку.

### iOS: App Transport Security

Источник: [NSAllowsLocalNetworking](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking).

- Ключ `NSAllowsLocalNetworking` разрешает подключения к неполным именам, доменам `.local` и IP-адресам (IPv4 и IPv6).
- **Начиная с iOS 17 ATS по умолчанию не разрешает подключения к IP-адресам.** В iOS 10–16 они были разрешены.
- Отдельные IP-адреса и диапазоны CIDR можно добавить в словарь исключений ATS.
- Вывод: собственной сборке приложения нужен `NSAllowsLocalNetworking` или точечное исключение. Глобальный `NSAllowsArbitraryLoads` не нужен.

### iOS: доступ к локальной сети

Источник: [TN3179: Understanding local network privacy](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).

- При первом обращении приложения к локальной сети система показывает запрос. Решение запоминается и меняется в «Настройки → Конфиденциальность и безопасность → Локальная сеть».
- Исходящее TCP-соединение на адрес локальной сети требует этого доступа. Проверка встроена в сетевой стек и действует на все API.
- Разрешение имени `.local` тоже требует этого доступа.
- Приложение должно объявить `NSLocalNetworkUsageDescription`.
- Система может отклонить первую операцию до ответа пользователя на запрос. Рекомендуется повторная попытка.
- **Трафик из Safari этого доступа не требует.** Поэтому проверка в браузере телефона не проверяет это разрешение.
- Локальная сеть — это Wi-Fi и Ethernet. Сотовая сеть и VPN к ней не относятся.

### Android: cleartext

Источники: [Network security configuration](https://developer.android.com/privacy-and-security/security-config), [expo-build-properties](https://docs.expo.dev/versions/latest/sdk/build-properties/).

- Начиная с Android 9 (API 28) HTTP без шифрования по умолчанию запрещён.
- Разрешить можно глобально (`cleartextTrafficPermitted="true"` в `base-config`; документация называет это небезопасной конфигурацией) или для отдельного домена через `domain-config`.
- В документации `domain-config` описаны только имена хостов. **IP-адреса, маски и диапазоны CIDR не упоминаются.**
- В Expo флаг `usesCleartextTraffic` задаётся через `expo-build-properties`. Он глобальный для приложения.

### Expo ImagePicker

Источник: [ImagePicker, SDK 57](https://docs.expo.dev/versions/latest/sdk/imagepicker/).

- Для `launchImageLibraryAsync` запрашивать разрешение на галерею не нужно.
- `allowsMultipleSelection` работает на Android и iOS 14+. Несовместим с `allowsEditing`.
- `selectionLimit: 0` означает системный максимум.
- На iOS есть `preferredAssetRepresentationMode`: `Automatic` (по умолчанию), `Compatible` («наиболее совместимое представление»), `Current` («без перекодирования, если возможно»).
- Документация прямо упоминает, что оригинал может вернуться в HEIC или AVIF. Гарантии JPEG она не даёт.
- `quality` на iOS игнорируется для PNG и BMP из галереи.
- Поля результата: `uri`, `mimeType` (может быть `null`), `fileName`, `fileSize`, `width`, `height` (могут быть 0).
- Библиотека входит в Expo Go.

### Expo Go: собственные сетевые настройки

Источник: [Info.plist Expo Go, ветка main](https://github.com/expo/expo/blob/main/apps/expo-go/ios/Exponent/Supporting/Info.plist).

- В Expo Go для iOS задано `NSAllowsArbitraryLoads = true` и объявлен `NSLocalNetworkUsageDescription`.
- Следствие: в Expo Go ограничения ATS на наш код не действуют. Успешный запрос из Expo Go ничего не говорит о поведении собственной сборки.

## 2. Результаты реальных проверок

Окружение: macOS, Node 22.22.3, LAN-адрес компьютера `192.168.1.10`, имя `My-Mac.local`, встроенный firewall macOS выключен.

Код: `spike/server.mjs`, без зависимостей.

| 2 | `/health` по LAN-IP `192.168.1.10` | `{"ok":true}` |
| 3 | `/health` по имени `.local` | `{"ok":true}` |
| 4 | Запрос без токена | 401 |
| 5 | Запрос с неверным токеном | 401 |
| 6 | Запрос с верным токеном в заголовке | 200 |
| 7 | Токен в URL вместо заголовка | 401 |
| 8 | Preflight `OPTIONS` с `Origin: null` | 204, `Access-Control-Allow-Origin: *`, разрешён заголовок `Authorization` |
| 9 | Загрузка PNG (698 КБ) по LAN-IP | Принят, тип определён по содержимому как `image/png` |

### Шаг 1. Запрос из браузера телефона

Пользователь сообщил, что браузер телефона показывает `{"ok":true}`.

В журнале сервера за это время есть запросы `GET /health` с двух разных устройств сети: `192.168.1.21` и `192.168.1.22`, по два запроса с каждого. Сервер доступен из локальной сети.

Не зафиксировано: какое из устройств iOS, какое Android, и открывался ли адрес по имени `.local` (сервер не записывал заголовок `Host`).

### Шаг 2. Плагин-заглушка

Код: `spike/figma-plugin/`.

**Импорт манифеста с IP-адресом отклонён.** Настольное приложение Figma при импорте выдало:

```
Manifest error: Invalid value for devAllowedDomains. 'http://127.0.0.1:8787' must be a valid URL.
```

В списке были, по порядку: `http://localhost:8787`, `http://127.0.0.1:8787`, `http://192.168.1.10:8787`, `http://my-mac.local:8787`. Ошибка указала на вторую запись, значит `http://localhost:8787` проверку формата прошёл. Вывод: IP-адрес в `devAllowedDomains` Figma не принимает. Запись с LAN-IP отдельно не проверялась, но она того же вида. IP-адреса из манифеста убраны.

Результаты запуска в настольном приложении Figma:

| Адрес | Манифест | iframe без токена | iframe с токеном | main-поток с токеном |
|---|---|---|---|---|
| `http://localhost:8787` | принят | HTTP 200 | HTTP 200 | HTTP 200 |
| `http://127.0.0.1:8787` | **отклонён** | — | — | — |
| `http://192.168.1.10:8787` | не проверялся, убран | — | — | — |
| `http://my-mac.local:8787` | принят | `Failed to fetch` | `Failed to fetch` | ошибка |

Наблюдения по журналу сервера:

- Запросы на `localhost` дошли. Перед каждым запросом с заголовком `Authorization` пришёл preflight `OPTIONS`, в том числе для запроса из main-потока. Собственный `fetch` Figma подчиняется CORS так же, как `fetch` в iframe (предположение A4 подтверждено).
- Запросы на имя `.local` до сервера не дошли: в журнале их нет. Блокировка происходит на стороне Figma. Причина не установлена (консоль плагина не смотрели). С этого же компьютера `curl` по этому имени отвечает.

**Вставка PNG:** исходник 800×600, узел 400×300, число узлов на странице выросло с 6 до 7.

**Запрос к неразрешённому домену** (`https://example.com`): `Failed to fetch`. Это согласуется с блокировкой по `networkAccess`, но текст ошибки CSP в консоли не проверялся.

**Уменьшение изображений больше 4096 px:** не проверено.

**Итог по адресам для плагина:** в MVP используется `http://localhost:<порт>`. Это единственный вариант, который принят манифестом и работает.

### Шаг 3. Экран в Expo Go

Код: `spike/mobile/` (шаблон `blank-typescript`, добавлен только `expo-image-picker`).

Шаблон Expo SDK 57 сам закрепил версии: `react-native 0.86.3`, `react 19.2.3`, `typescript ~6.0.3`. Это не последние версии из npm (0.87.1 и 7.0.2), а совместимые с SDK. В продукте используем версии, которые выбирает `npx expo install`.

Проверено на компьютере: `tsc --noEmit` без ошибок, `expo-doctor` 21 из 21, бандлы для iOS и Android собираются.

Запуск в Expo Go: iPhone с iOS 26.4 и Android с API 33 (Android 13). Expo Go открыл проект на SDK 57 на обоих (A10 подтверждено).

| Проверка | iOS 26.4 | Android 13 |
|---|---|---|
| Связь с сервером по LAN-IP из Expo Go | HTTP 200, с токеном HTTP 200 | HTTP 200, с токеном HTTP 200 |
| Запрос на доступ к локальной сети | не сообщено | — |
| Picker открывается без запроса доступа к галерее | не сообщено | не сообщено |
| Формат при выборе по умолчанию | **HEIC**, 3024×4032, 1,6 МБ | JPEG, 1080×2400, 0,7 МБ |
| Формат в режиме `Compatible` | **JPEG**, 3024×4032, 3,6 МБ | — |
| Формат при `quality: 0.9` | HEIC, тот же файл | не проверено |
| Отправка на сервер, первый способ | HTTP 200, сервер определил `image/heic` | **HTTP 415**, сервер не распознал изображение |

Выводы:

- A5 подтверждено: Expo Go на Android пропускает HTTP на LAN-IP.
- A7 подтверждено: по умолчанию iOS отдаёт HEIC.
- A8 подтверждено частично: `Compatible` даёт JPEG, `quality: 0.9` формат не меняет.
- Первый способ отправки (`fetch(uri).blob()` как тело запроса) на iOS передал файл целиком, на Android сервер получил не содержимое изображения. Что именно пришло, не зафиксировано: сервер тогда не записывал размер и первые байты. Заголовок `Content-Type` в этом способе до сервера не дошёл и на iOS (пришла пустая строка).
- Способ отправки заменён на явное чтение байтов файла (`File.bytes()` из `expo-file-system`) и `fetch` из `expo/fetch`. На телефонах новый способ не проверен.

### Шаг 4. Сквозной прогон

Плагин скачал файл HEIC, отправленный с iPhone, и не смог его декодировать: `The source image could not be decoded`. iframe плагина HEIC не читает, до `figma.createImage` дело не дошло.

**Вторая попытка, iOS: сквозной путь пройден для PNG.** С iPhone отправлен снимок экрана `IMG_0295.png` (1179×2556, 589 КБ). Сервер определил `image/png`, плагин вставил его в Figma. Повторено три раза подряд (три режима выбора), каждый раз успешно. Приложение на телефоне при этом работало на первом способе отправки: новый код не был загружен.

Для PNG режим выбора формат не меняет: во всех трёх случаях пришёл PNG.

**Вторая попытка, Android: причина ошибки 415 установлена.** Телефон тоже работал на первом способе отправки. Сервер получил 14 байт с текстом `File not found` вместо файла размером 415 КБ. Вывод: `fetch(uri).blob()` на Android не читает файл, выбранный через picker, и для отправки непригоден. Сеть и сервер здесь ни при чём.

**Третья попытка: второй способ отправки работает на обоих телефонах.** Приложение читает файл через `File.bytes()` и отправляет через `fetch` из `expo/fetch`.

| Телефон | Файл | Прочитано на телефоне | Получено сервером | Тип по содержимому | `Content-Type` |
|---|---|---|---|---|---|
| Android 13 | JPEG 1080×2400 | 415 637 байт | 415 637 байт | `image/jpeg` | дошёл |
| iOS 26.4, режим `Compatible` | JPEG 4284×5712, фото с камеры | 4 130 716 байт | 4 130 716 байт | `image/jpeg` | дошёл |

После каждой из двух отправок плагин скачал файл с сервера (есть в журнале сервера). Текст результата вставки для этих двух файлов не прислан, поэтому появление именно этих фото на странице Figma отмечено как не подтверждённое.

Фото с камеры iPhone (4284×5712) больше лимита Figma 4096 px. Уменьшение перед вставкой нужно для обычных фото, а не только для панорам.

**Уменьшение больших изображений (A9) подтверждено.** JPEG 6000×4500, созданный в iframe плагина, уменьшен через canvas до 4096×3072 и вставлен узлом 400×300. Число узлов на странице выросло с 15 до 16.

## Решения для MVP

### Адреса сервера

У клиентов разные адреса одного и того же сервера, они настраиваются раздельно:

| Клиент | Адрес | Статус |
|---|---|---|
| Телефон | `http://<LAN-IP>:<порт>`, вводится в настройках приложения | Кандидат, ждёт проверки с телефона |
| Плагин | `http://localhost:<порт>` | **Подтверждено проверкой** (настольное приложение Figma) |

Среда плагина: `localhost` работает, IP-адреса отклоняются манифестом, имя `.local` манифестом принимается, но запросы блокируются. Телефон из сети доступен по LAN-IP.

### Форматы изображений

Предварительный план, окончательно фиксируется после шагов 2 и 3:

| Формат | Обработка |
|---|---|
| PNG, JPEG, GIF до 4096 px | Передаются в Figma без изменений |
| PNG, JPEG больше 4096 px | Уменьшаются до 4096 px по большей стороне в iframe плагина через canvas (проверено) |
| HEIC | Figma не принимает, iframe плагина не декодирует (проверено). Приложение вызывает picker с `preferredAssetRepresentationMode: Compatible`, и iOS отдаёт JPEG (проверено на iOS 26.4; файл получается примерно вдвое больше исходного HEIC). Сервер HEIC не конвертирует и отклоняет его с понятной ошибкой. Запасной вариант — конвертация на телефоне через `expo-image-manipulator` |
| Прочее (WebP, AVIF и т. д.) | Отклоняется сервером |

### Безопасность

- Токен — временный механизм для личного MVP в домашней сети. Для публичного сервиса он недостаточен: трафик по HTTP не шифруется, токен общий и не отзывается.
- Глобальные защиты системы не отключаются, проброс портов на роутере не настраивается.
- Встроенный firewall macOS на этом компьютере уже выключен, эксперимент его не менял. Если его включить, macOS при первом запуске спросит разрешение на входящие подключения для `node`.

## Что изменится вне Expo Go

Требования магазинов и платформ (не архитектурные улучшения):

- **iOS.** Собственной сборке нужны `NSAllowsLocalNetworking` и `NSLocalNetworkUsageDescription`. Подтверждено документацией, на практике не проверено.
- **Android.** Собственной сборке нужно явное разрешение cleartext либо HTTPS. Способ без глобального флага не найден (A6).
- **Figma Community.** Адрес сервера должен быть в `allowedDomains` с заполненным `reasoning`: `devAllowedDomains` действует только при разработке.

Отдельно, как вопрос масштабирования, а не требование публикации: постоянное хранилище очереди, раздельные токены, HTTPS.
